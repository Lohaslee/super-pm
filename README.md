# Super PM

这个需求是真的吗？用户为什么要放弃现在的做法？如果只能做好一件事，应该是什么？又有哪些东西看起来很诱人，但这次坚决不能做？

这些问题，我自己做产品时也反复遇到。AI 可以很快列出功能、写出 PRD，却不一定能陪我把产品真正想明白。有时文档越完整，一个没被验证的假设反而越像事实。

后来我想到，自己这些年了解和学习过几位很厉害的产品大师。面对同一个问题，他们会从哪里追问，会做出什么取舍，又会因为什么改变判断？我想把这些不同的产品视角整理到一起，让它们真正参与需求讨论，而不只是留在书摘和笔记里。

`super-pm` 就是这样做出来的。它不是替你写文档、管流程或堆术语，而是陪你分析需求、拆开事实与假设、讨论取舍，把一个模糊想法慢慢收敛成可以验证、可以交付的产品方向。

它最初是为独立开发者验证 0→1 想法而做的，也能用来诊断已有产品。软件、AI、硬件、服务、内容、平台、企业产品和线下体验都可以讨论。希望它也能在你准备动手做产品时，帮你少走一点弯路。

## 能做什么

- **负向边界优先**：沿用已知边界；只有缺失边界会改变判断时，才追问不能接受的结果、本次不做的功能、硬约束和必须保护的产品品质。
- **区分事实与假设**：分开记录用户原话、事实、推断、建议和待验证假设，不用肯定语气掩盖未知。
- **动态组织产品视角**：每个决定只设一个主责视角，其他视角只有能提出不同方案或关键风险时才加入。
- **允许指定主 PM**：你可以选择一位老师负责整体方向，其他老师补充和挑战，但最终仍以用户边界和可信证据为准。
- **适配不同产品类型**：按问题选择需求与价值、产品系统、使用与交付、触点与形态、体验与信任等维度，不机械套固定框架。
- **先验证高风险假设**：先给出最低成本的验证方案，再询问是否搜索资料、检查竞品或运行原型；未经允许不会执行。
- **按需沉淀产品决定**：高价值决定收敛时会提议一次是否保存；只有你授权后才写入 `.super-pm/decisions.md`，方向改变时保留被替代的历史决定。
- **知道什么时候退出**：纯工程实现只确认必要的产品约束后就进入开发；法务、税务、审计和专业财务结论会交给相应专业能力，不硬套产品视角。
- **随时输出简报、报告或 PRD**：独立开发与早期对齐可用一页决策简报；方向收敛后可产出供 AI coding agent 或团队直接开发的完整 PRD。
- **保留老师的判断味道**：中文原则库不再停在每位 10 条；重要回答可以用一句最相关老师的原话点题，但不会机械轮流发言或把金句当结论。

默认会用一个尽量短的决策循环：说清问题，给出建议，提出最强反对意见，检查负向边界，再确定下一步验证。只有进入开发、跨多个产品维度，或面对昂贵、不可逆、安全及合规决策时，才展开完整定义。

## 七个产品视角

七套产品经验以化名呈现。它们是判断问题的方法，不是真人模拟，也不会为了凑人数轮流发言。

| 视角 | 主要关注 |
|---|---|
| 乔老师 | 聚焦、取舍、完整体验、产品品质与叙事 |
| 张老师 | 人性、克制、自然交互、注意力与社交压力 |
| 梁老师 | 用户状态、情绪驱动力、真需求、系统能力与机会判断 |
| 俞老师 | 用户价值、替换成本、交易结构、优先级与假设验证 |
| 王老师 | 本质思考、一手用户洞察、突破机制、内容与推荐产品 |
| 李老师 | 产品定义、核心体验、商业闭环、组织与规模化 |
| 雷老师 | 时机、专注执行、性价比、口碑、用户参与与复盘 |

不同意见会被保留下来，再依据用户边界、事实证据、用户价值、交付能力和可逆性做出取舍。对话偶尔会自然带出不同视角的表达方式，但不会冒充真人、编造引语或暗示任何老师为具体产品背书。

## 语言与输出

- 默认使用简体中文；用户主要使用英文时自动切换为英文。
- 中英文资料独立维护，只加载当前语言所需的内容。
- 保留用户原有的产品名、指标和已确认原话，不擅自翻译。
- 表达专业但不堆黑话：内部推理完整，对外只讲影响决定的内容；适当保留有价值的老师意见和框架名并顺手解释，内部原则编号默认不展示。
- 有实质判断时，偶尔会在结尾补一句与当前取舍直接相关的老师提醒；每次最多一句，不作为固定签名。
- 报告和 PRD 是可选产物，不是讨论的默认终点。

## 安装

在 Codex 中输入：

```text
Install the skill from https://github.com/Lohaslee/super-pm/tree/main/skills/super-pm
```

安装完成后，通过 `$super-pm` 调用。

## 使用示例

```text
使用 $super-pm 直接判断：相册 App 要不要加每日签到？能一轮回答就不要展开完整流程。
```

```text
使用 $super-pm 帮我分析这个产品想法。先问清楚我不想做成什么，不要急着写 PRD。
```

```text
使用 $super-pm，让雷老师担任主 PM，其他视角配合，帮我验证这个 0→1 想法。
```

```text
使用 $super-pm，把目前确认的判断、假设和分歧整理成一份产品报告。
```

```text
使用 $super-pm，把目前确认的产品决策整理成一份可直接进入开发的 PRD。
```
